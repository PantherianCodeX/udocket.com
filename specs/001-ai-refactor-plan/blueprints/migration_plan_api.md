# `/migrations/backlog` API Blueprint

## Endpoint
- `GET /migrations/backlog`
- Returns prioritized modernization tasks aligned with LangGraph stages.

## Response Shape
```json
[
  {
    "task_id": "MIG-001",
    "title": "Modernize analyze.gaps_extract",
    "stage_key": "analyze.gaps_extract",
    "status": "blocked",
    "dependencies": ["analyze.context_builder"],
    "effort_low": 5,
    "effort_high": 8,
    "critical_path": true,
    "qa_gates": ["gap_diff_hash"],
    "cost_ceiling": 0.3
  }
]
```
- Mirrors schema referenced in `contracts/openapi.yaml` under `MigrationTask` (to be added during implementation if missing).

## Behavior
- Backend loads `data/backlog/migration_backlog.json` generated by the prototype script and, once productionized, from Postgres.
- Supports optional `stage_key` and `critical_path` filters via query params (future enhancement).
- Sets `X-Readiness-Hash` header to the digest reported by `ReadinessService` so clients correlate backlog snapshots with readiness datasets.

## Validation
- JSON Schema enforcement via Spectral; ensures numeric fields remain positive and dependencies reference valid task IDs.
- Response arrays are sorted by dependency order (topological) to keep UI deterministic.

## Observability
- Emits `backlog_fetch` metric with counts + filters.
- Logs audit linkage referencing `reports/dependency_story.md` entry to preserve planning context.
