# Ops & Audit Artifact Manifest

Planning activities for the AI Module Migration initiative must keep evidence local to the feature directory so future implementation can ingest it deterministically. This manifest defines the directories, file names, and handling rules for ops JSONL and audit outputs produced during the planning sprint.

## Directory Layout (under `specs/001-ai-refactor-plan/`)

| Type | Path | Contents |
|------|------|----------|
| Ops logs | `reports/readiness_ops.jsonl` | Append-only LangGraph readiness recompute logs generated by `scripts/refresh_readiness.py`. Each record is a single-line JSON object with `timestamp`, `stage_key`, `owner_team`, `action`, and `artifact_hash`. |
| Audit trail | `reports/audit/readiness_audit.jsonl` | Mirror of ops entries plus reviewer/approver metadata; kept in lockstep with ops entries for governance review. |
| Hash seals | `reports/audit/seals/YYMMDD-HHMMSS.sha256` | One file per ops run storing the SHA256 of the JSONL payload plus LangSmith/LangFuse evidence references. |
| Tooling evidence | `reports/langsmith_*.json[l]`, `reports/langfuse_*.md` | Outputs from LangSmith/LangFuse workflows (see Phase 5 tasks). Cross-link their hashes back to the audit JSONL via `artifact_hash`. |
| Risk/activation | `reports/risk_log.jsonl`, `reports/activation_*.md` | Other append-only logs referenced by ops entries through `related_artifact` IDs. |

```
reports/
├── readiness_ops.jsonl
├── langsmith_eval_results.json
├── langfuse_enable_disable.md
└── audit/
    ├── readiness_audit.jsonl
    └── seals/
        └── <timestamp>.sha256
```

## Writing Rules
1. **Append-only**: Never rewrite existing JSONL lines. New runs add entries at the end and emit a matching seal file.
2. **Hash linking**: Each ops record stores `artifact_hash` (SHA256 of the serialized readiness dataset) and `audit_reference` (relative path to the audit JSONL with the same timestamp). Seal files hash the ops payload *and* the audit entry to create an immutable chain.
3. **Timezone discipline**: Encode timestamps in UTC ISO-8601 (`2025-11-14T23:41:00Z`) for both ops and audit streams.
4. **Evidence pointers**: When LangSmith/LangFuse evidence or readiness datasets are produced, capture their relative paths in the `evidence` array so later automation can copy the artifacts into `storage/ops/`.
5. **Local-only during planning**: Keep everything scoped to `specs/001-ai-refactor-plan/` until the devops readiness module lands. Implementation will promote finalized artifacts into `storage/ops/` and Postgres.

## Generation Flow
1. Run `python specs/001-ai-refactor-plan/scripts/refresh_readiness.py --lane modernization`.
2. The script writes `reports/readiness_ops.jsonl` and `reports/audit/readiness_audit.jsonl` in a single transaction, then populates `reports/audit/seals/<timestamp>.sha256`.
3. Datasets under `data/readiness/` carry matching hashes so the ingest service (`packages/devops/readiness/service.py`) can verify immutability later.
4. When ops records cite LangSmith/LangFuse outputs, they must also include the `VendorUsageBudget` snapshot ID for cost traceability.

## Validation Checklist
- ✅ Every ops entry has `artifact_hash`, `audit_reference`, and `evidence` fields.
- ✅ Audit JSONL lines include `actor`, `action`, `result`, and `justification` fields per LangGraph spec §8.3.
- ✅ Seal files exist for every ops run and contain the SHA256 digest across the concatenated ops + audit payloads.
- ✅ No artifact leaves the feature directory until implementation merges.
